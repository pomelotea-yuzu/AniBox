# 提案：把数据根迁到产品目录（`.anibox/` / `data/`）

- 状态：实施中（2026-11-22 起）
- 关联不变量：I7（便携优先）、I12 类口径（不默认写系统用户目录）

## 为什么改

`docs/knowledge/invariants.md` 的 I7 一直写着"业务数据跟随产品目录"，但实际只有便携包做到了
（靠 `.portable` 标志重定向到 `<软件目录>/data`）。开发态仍然写 Electron 默认 `userData`
（系统用户目录下的 `anibox`，即 `%APPDATA%\anibox`），后果有三个：

1. **开发数据跟仓库分离**：库、进度、索引缓存散在系统用户目录，删仓库或备份仓库都带不走它；
2. **文档说谎**：README 与不变量写着"便携优先 / 拷走即迁移"，开发态其实不是；
3. **换机器/清盘即丢**：调试用的库与索引缓存动辄几百 MB，重建成本高。

## 范围

- 新增数据根解析的三档优先级（env → 便携 → 开发态 `.anibox/` → 安装版默认）；
- 重定向后执行一次性旧数据迁移（沿用已有的 `migrateLegacyUserData`）；
- 启动日志打印实际数据目录，便于用户自查；
- 内置索引在开发态也从 `apps/desktop/resources/` 安装（原先只在打包态生效）。

## 明确不做

- **不改安装版（NSIS）的行为**：安装版保持系统 `userData`。它没有可携带的产品目录，硬改会让
  "卸载即清除"失效。
- **不动设置页 UI**：数据目录展示仍欠着，记在 `docs/knowledge/debt.md`，不塞进本 change。
- **不搬 `models/` 与 `yuc-covers/` 的既有开发副本**：它们已随 `apps/desktop` 落位，且都是可重建的
  缓存/模型；本 change 只管"今后的写入去哪"。
