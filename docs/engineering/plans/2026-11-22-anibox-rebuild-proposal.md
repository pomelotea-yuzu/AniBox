## 1. 已明确的方向

- **Windows 继续是 AniBox 的主平台。** 不把 macOS 适配列入本轮；RIFE 能在部分 Mac 上运行，不等于 AniBox 或主机采集链路已能移植。
- **采用 Layress 的仓库治理和开发范式。** 不是只加一页 README 或一个聚合命令，而是把接手入口、目录归属、OpenSpec、经验库、产物隔离和两端门禁当作同一套基础设施。照搬规则和目录角色，替换 Layress 专属模块名、产品约束与远程配置。
- **倾向新开一个干净的根目录，再迁移。** 新路径、是否继承 Git 历史、是否继续使用现有远程，还未决定。旧仓库与现有版本保持原样，新根能构建、验收通过后再讨论切换。
- **先把三类体验分开立项。** 电视模式、Windows 本地视频插帧、串流画面适配是三条独立 change；不能因为某段视频上 RIFE 跑通，就承诺采集游玩或电视客户端也可用。


- 根目录保留统一 workspace 命令。现用产品依赖、Electron 构建和便携打包路径逐项迁移，不把 Layress 尚未实现的包结构当成 AniBox 现有能力。
- 洁净度采用 Layress 的三层机制：`.gitignore` 明确归属、脚本对高风险文件默认拒绝、`.git-hygiene-allowlist` 留可审计理由。安装包、模型、媒体库、日志、凭据和本机绝对路径配置不进历史；图标等必须入库的资源单独说明。
- 现有便携包的 `data/` 及外部媒体位置不动，不自动搬迁、覆盖或改写。新根的开发数据与旧版隔离；迁移验证使用用户数据的副本，不拿原件试错。

### OpenSpec 的操作顺序

先迁移项目骨架，再设活动 change `rebuild-repo-foundation`。后续每个非平凡 change 走同一链路：`proposal.md`（为什么改、范围）→ `design.md`（取舍与回退）＋ `specs/`（需求与场景）＋ `tasks.md`（验收步骤）→ 审阅放行 → 实施 → `evidence-index.md`（证据与未验项）→ 归档并合入主 spec。命名用动词开头的 kebab-case；已归档变更、现行规格和说明冲突时，以源码与可复核证据为准。

把当前实际可运行的版本作为迁移基线。现有类型检查通过，但 Lint 有存量错误，且本环境未能启动 Vitest；不把这些结果当新仓已通过，也不靠降低规则过门禁。先建立可执行的基础门禁，再按验证结果接入产品检查。Windows 实机、遥控器和采集卡验收单列。

## 3. 产品方向与验收线

| 候选 change | 首版做什么 | 不做 / 怎么验 |
|---|---|---|
| `add-windows-tv-mode` | Windows 接 HDMI，电视作为显示器。电视全屏片库、大字号、清楚的焦点高亮；用方向键/手柄完成选番、继续观看、切集和退出。解码、字幕及将来的滤镜仍由电脑完成。 | 暂不做电视原生 App，也不承诺电视遥控器能经 HDMI 控 Windows。真实电视上从片库到播放再返回，全程不碰鼠标，退出后能回到原选中项。 |
| `add-windows-rife-playback` | 从本地动画入手：先用同一片段做 24→48 fps 离线 A/B，再测 RTX 3060 6GB 实时 2×。RIFE 是视频插帧，不接 DLSS；可先测 ncnn/Vulkan，再用 TensorRT 做 Windows/NVIDIA 性能对照，不预选最终后端。 | 暂不承诺 1080p 实时或 24→60，也不改源文件。检查横移、重复帧、切镜、字幕和人物轮廓；记录丢帧、帧时间、显存、音画同步和 seek 后恢复。默认关闭，撑不住应回退原始帧率，不能拖慢原播放。 |
| `adapt-live-capture-streams` | 区分**输入**与**输出**。输入：PS→HDMI 采集卡→Windows 预览/插帧→电脑屏幕或电视，手柄直接连 PS；先做 1080p 30→60、不开超分，测不稳再降到 720p。输出：Windows 片库→局域网电视端，先让电视直解，按需转封装/转码，单独验证字幕、音轨和进度。 | 采集链路用同一场景比 HDMI 直通、采集预览、采集＋插帧，记录端到端延迟、实际呈现帧率及 HUD/快速转镜伪影。采集标称 60 Hz 可能只是重复 30 帧，需以实际独立画面为准。不把补出的 60 FPS 写成原生 60 或更低输入延迟；不承诺首版无线串流也带实时增强。 |

串流试验可用 SmoovPlay 作为 RIFE 参考（采集卡仍属实验），或用 OBS 窗口投影＋Lossless Scaling 先比较手感（这条不是 RIFE）。本地播放与采集可以复用帧输入/输出和算法接口，但本地端可用缓冲换稳定，互动采集端要限制队列、允许旁路；两者不共用同一验收阈值。

**不在首版范围**：Mac 正式发行、独立电视端、本地硬盘直插电视播放承诺、DLSS 4/5、120 FPS 采集插帧、超分与插帧一起开。是否加入由各自的实测和 change 决定。

## 4. 放行顺序与待拍板项

1. **先定新根与 Git 策略**：A. 新目录、新 Git 历史，旧仓作为历史参考；B. 新目录、保留原 Git 历史，用新分支或并行仓迁移。两者都不需要移动现目录、删除旧仓或强推。远程、命名、版本发布由维护者确认。
2. **搭骨架并迁移最小桌面基线**：只迁源码、必要资源和可复现构建；盘点实际需要的运行库。先确认能够安装依赖、构建、启动、扫描、播放、续播、切音轨和字幕、生成便携包。新旧两份可并存，打包用显式输入路径，避免误取旧暂存目录。
3. **逐项放行产品 change**：建议电视模式先建立可见的客厅体验；RIFE 并行做独立小样但先不接播放器；直播采集和局域网电视客户端按验证结果分别实施，必要时拆成两个 change。
