# docs/knowledge/ · 经验库

> 本文默认以中文维护。

**这是本仓最重要的机制。** 开发中踩的坑、实机硬事实、不许重开的不变量与关键决策**全部入库**，
任何人（或任何智能体）clone 之后即可接手，不依赖某个人的本机记忆目录。

## 五个专题，按主题不按日期

| 文件 | 收什么 | 什么时候写 |
|---|---|---|
| [`engineering.md`](engineering.md) | 构建、打包、门禁、依赖、脚本通道上的坑 | 踩到时立刻 |
| [`runtime-probe.md`](runtime-probe.md) | libmpv 渲染、帧率、音轨/字幕、seek 的实机硬事实 | 实机验证通过/失败时 |
| [`invariants.md`](invariants.md) | **不许重开的架构不变量**，每条给出不成立时的后果 | 一个坑第二次踩时晋升 |
| [`decisions.md`](decisions.md) | 关键决策速查：决定 / 理由 / 代价 / 推翻条件 | 定了路线时 |
| [`debt.md`](debt.md) | 未决口径与欠账，标注归谁定夺 | 发现"现在做不到"时 |

## 条目格式（固定，不许自创）

```
- [YYYY-MM-DD][级别] 现象 ⇒ 根因 ⇒ 规避 ⇒ 证据
```

- 级别：`P0` 致命（崩溃/数据丢失）/ `P1` 会误判（看起来通过其实错了）/ `P2` 浪费时间。
- **一条一行一主题。** 只写结论，不写过程；过程写在对应 change 的 `design.md` / `evidence-index.md`。
  几百字挤一行的日期日志，下个接手人只会跳过。
- **证据**写可复核的东西：文件与行号、命令、实测数值、issue/commit。写不出证据的先别写。
- **同一坑第二次踩 ⇒ 升级**：从条目升进 `invariants.md`，或直接变成门禁/脚本断言。
  靠记性防的坑一定会再踩；只有代码拦住的才算防住。
- **机器 PASS ≠ 人工通过**。画面、字幕、音轨类判定归实机复核；未执行的项单列"未执行"。

## 与 OpenSpec 的关系

- 经验库是**跨 change 的沉淀**；单个 change 的推导过程留在 `openspec/changes/<name>/`。
- 一条经验如果变成"以后都必须这样"，就同时改 `openspec/config.yaml` 的不变量清单
  （I1–I11）并在 `invariants.md` 写出后果——两处必须一致。
