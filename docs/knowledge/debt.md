## 工程

- **ESLint 存量错误未清**：`npm run lint` 仍失败，因此 `npm run check`（typecheck → lint → test）不能作为门禁。
  归维护者；必须在下次接入 CI 产品检查前清完，或显式把规则降级并记录理由。
- **Vitest 在本机沙箱未能启动**：`npm test` 尚未实际跑通（依赖安装/环境问题），CI 里也没有测试步骤。
  归维护者；接 CI 前必须确认一次真实绿灯，否则"有测试"是空话。
- **打包脚本与版本号耦合**：`mk-stage121.py`、`pack-zip-123.py` 名字里带版本，每次发版靠复制改名；
  `pack-zip-123.py` 里还写死了 1.2.3 的路径。应改为单一入口 + 版本参数。归维护者，下一个发布 change 里处理。
- **`electron-builder.yml` 未走通**：配置存在但与手动流水并存，容易出现"改了 yml 但打包不走它"的误解。
  要么让它真正可用，要么在 yml 顶部注明"当前不参与出包"。

## 数据与匹配

- **持久化数据里存了绝对路径**：`store` 的 `coverPath` 与季节缓存中的封面路径都是绝对路径，
  所以换数据根（本次 `.anibox` 迁移）或换盘、换机器之后，旧路径会先被读一次；旧副本一旦删除就全裂。
  这与 I7「拷走即迁移」直接冲突。归维护者；修法是路径相对数据根存储，或只存封面 hash 在读时用当前
  数据根解析。证据见 `engineering.md` 2026-11-22 条目。

- **季号对齐弱**：「XX 第二季」在精确匹配下会命中第一季的 base 条目，导致封面/简介张冠李戴。
  现状靠人工改绑。归维护者；需要 AI 消歧或更强的季号解析，属独立 change。
- **约 47% 的条目没有别名**：这些条目只能用日文原名匹配，romaji 标题命中不了，扫库时容易漏刮。
  归维护者；需要 romanization（本地离线方案优先）。
- **设置页的索引 UI 还没接线**：`index:status` / `index:checkUpdate` / `index:update` 三个 IPC 已备好，
  界面没接。归维护者；做索引自动更新时一并做。

## 便携与存储

- **数据根已重定向（2026-11-22 已偿）**：开发态写仓库根 `.anibox/`、便携版写 `<软件目录>/data`、
  可用 `ANIBOX_DATA_DIR` 覆盖；首次启动会把系统 `userData` 里的旧数据搬一次（跳过 Chromium 缓存与
  `stream-cache`）。**仍未做**：设置页/启动画面里展示当前数据目录（目前只有控制台日志），
  用户仍无法在 UI 里自查——I7 的可验证性还差这一步。
- **安装版（NSIS）仍用系统 `userData`**：与便携版口径不同，属有意设计（安装版没有可携带的产品目录）。
  若将来要统一，得先决定"安装版的数据放哪"。
- **便携包目录里的 `data/` 仍是用户数据**：`pack-zip` 已排除，但升级覆盖时如何保留需再确认。

## 分发

- **push 与 Release 归用户**：本地 commit 由智能体做，双远程（Gitee `origin` / GitHub `github`）的 push、
  tag、Release 文案发布都由用户操作。GitHub 账号曾有 abuse 误判，push 频率需控制。
- **Gitee 高危词限制**：仓库名/README 命中「BT、磁力、种子、代理、镜像」等词会被 451；
  文案与文档里一律避免，也不要做成规避性的黑话。
